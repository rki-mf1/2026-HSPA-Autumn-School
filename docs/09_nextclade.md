# Mpox lineage assignment and phylogenetic placement with Nextclade

In this tutorial, you will use **Nextclade CLI** to analyze the consensus genome sequences generated with `artic-mpxv-nf`.

The analysis uses the official Nextclade dataset:

```text
nextstrain/mpox/all-clades
```

This dataset covers **MPXV clades I, IIa, and IIb** and can be used for clade and lineage assignment, sequence quality control, mutation analysis, and phylogenetic placement.

---

## 🎯 Learning objectives

By the end of this tutorial, you will be able to:

- Identify the consensus FASTA files produced by `artic-mpxv-nf`
- Combine multiple consensus genomes into a single multi-FASTA file
- Run Nextclade from the command line
- Use the `nextstrain/mpox/all-clades` dataset
- Generate Nextclade tabular, sequence, and phylogenetic outputs
- Interpret key Nextclade results, including clade, outbreak lineage, QC status, mutations, and missing data

## Find the consensus genomes generated by `artic-mpxv-nf`

First, locate the consensus FASTA files:

```bash
find "$ARTIC_DIR" -type f -name "*.consensus.fasta"
```

Each file should represent the reconstructed consensus genome of one sample or barcode.

Before continuing, check how many consensus FASTA files were produced:

```bash
find "$ARTIC_DIR" -type f -name "*.consensus.fasta" | wc -l
```

---

## Combine the consensus genomes into one FASTA file

Nextclade can analyze multiple sequences at once. For convenience, combine the individual consensus FASTA files into one multi-FASTA file:

```bash
find "$ARTIC_DIR" -type f -name "*.consensus.fasta"     -exec cat {} +     > "$NEXTCLADE_DIR/yale_testrun1_cladeii.consensus.fasta"
```

The resulting file will contain all reconstructed genomes:

```text
$NEXTCLADE_DIR/yale_testrun1_cladeii.consensus.fasta
```

Check how many sequences are present:

```bash
grep -c "^>" "$NEXTCLADE_DIR/yale_testrun1_cladeii.consensus.fasta"
```

This number should match the number of consensus FASTA files found in the previous step.

You can inspect the FASTA headers with:

```bash
grep "^>" "$NEXTCLADE_DIR/yale_testrun1_cladeii.consensus.fasta"
```

> **Important**
>
> Each sequence should have a unique FASTA header. Nextclade uses the sequence name to identify samples in its output files.

## Check the available MPXV datasets

Nextclade provides pathogen-specific datasets containing the reference genome, genome annotation, phylogenetic tree, QC configuration, and clade definitions required for analysis.

To search for MPXV datasets:

```bash
nextclade dataset list --only-names | grep mpox
```

You should see datasets including:

```text
nextstrain/mpox/all-clades
nextstrain/mpox/clade-i
nextstrain/mpox/clade-iib
nextstrain/mpox/lineage-b.1
```

For this tutorial, use:

```text
nextstrain/mpox/all-clades
```

The **all-clades** dataset is appropriate when samples may belong to different MPXV clades or when you want Nextclade to determine their clade without assuming it beforehand.

## Run Nextclade

Run Nextclade directly with the official MPXV all-clades dataset:

```bash
nextclade run     --dataset-name "nextstrain/mpox/all-clades"     --output-all "$NEXTCLADE_DIR/results"     "$NEXTCLADE_DIR/yale_testrun1_cladeii.consensus.fasta"
```

Nextclade will automatically download the latest compatible version of the dataset and use it for the analysis.

---

## Command explanation

### `nextclade run`

```bash
nextclade run
```

Starts a Nextclade sequence analysis.

Nextclade performs several analyses, including:

- alignment to the dataset reference
- nucleotide mutation calling
- amino-acid mutation calling
- sequence quality control
- clade assignment
- lineage-related annotation
- phylogenetic placement

The exact analyses available depend on the contents of the selected dataset.

---

### `--dataset-name`

```bash
--dataset-name "nextstrain/mpox/all-clades"
```

Tells Nextclade to automatically obtain and use the official MPXV **all-clades** dataset.

The dataset contains the pathogen-specific resources needed for analysis, including the reference sequence and phylogenetic information.

The official dataset name is:

```text
nextstrain/mpox/all-clades
```

This dataset includes MPXV representatives from **clades I, IIa, and IIb**.

---

### `--output-all`

```bash
--output-all "$NEXTCLADE_DIR/results"
```

Tells Nextclade to write all standard output types into the specified directory.

Nextclade will create the directory automatically if necessary.

Typical output files include:

```text
nextclade.tsv
nextclade.csv
nextclade.json
nextclade.ndjson
nextclade.aligned.fasta
nextclade.auspice.json
```

Depending on the installed Nextclade version and dataset, additional output files can also be produced.

For routine workshop interpretation, the most useful file is usually:

```text
nextclade.tsv
```

---

### Input FASTA

```bash
"$NEXTCLADE_DIR/yale_testrun1_cladeii.consensus.fasta"
```

The final positional argument is the FASTA file containing the query sequences to analyze.

In this tutorial, it contains the consensus genomes produced by `artic-mpxv-nf`.

Nextclade CLI can accept one or multiple FASTA files as input.

## Inspect important result columns

Nextclade reports many columns. First, inspect the header:

```bash
head -n 1 "$NEXTCLADE_DIR/results/nextclade.tsv"     | tr '\t' '\n'
```

Important fields for MPXV interpretation can include:

| Field | Interpretation |
| --- | --- |
| `seqName` | Sample / sequence identifier |
| `clade` | Assigned MPXV clade |
| `outbreak` | Outbreak designation used by the MPXV dataset |
| `lineage` | Assigned lineage |
| `outbreakLineage` | Outbreak and lineage combined into an unambiguous designation |
| `qc.overallScore` | Numerical overall QC score |
| `qc.overallStatus` | Overall Nextclade QC category |
| `totalMissing` | Number of missing nucleotide positions |
| `totalSubstitutions` | Number of nucleotide substitutions relative to the reference |
| `totalDeletions` | Total deleted nucleotide positions |
| `totalInsertions` | Total inserted nucleotide positions |
| `substitutions` | Individual nucleotide substitutions |
| `aaSubstitutions` | Amino-acid substitutions |

The exact columns can vary between Nextclade versions and dataset versions.


>
> Do not assume fixed column numbers between Nextclade versions. Always inspect the header first.

## Understanding MPXV lineage names

The current MPXV Nextclade datasets distinguish between:

- **clade**
- **outbreak**
- **lineage**
- **outbreakLineage**

This distinction is important because lineage names can be reused between different MPXV outbreaks.

For example, an unambiguous designation can look like:

```text
sh2017/B.1
```

or:

```text
sh2023/A.1
```

The `outbreakLineage` field combines the outbreak and lineage and should therefore be preferred when reporting a lineage in contexts where the lineage name alone could be ambiguous.

---

## Interpret the QC status

Nextclade performs several quality-control checks.

The overall QC result is summarized in:

```text
qc.overallScore
qc.overallStatus
```

A poor QC result does **not automatically mean that the sample belongs to the wrong clade**.

Instead, inspect the underlying causes. Problems can arise from:

- large amounts of missing sequence
- low genome completeness
- unusual numbers of mutations
- frame shifts or unexpected stop codons
- problematic alignment regions
- sequencing or consensus-generation errors

For an amplicon sequencing workflow, large stretches of missing sequence can also result from **amplicon dropout**.

Therefore, Nextclade QC should be interpreted together with the coverage information generated by `artic-mpxv-nf`.

---

## Compare Nextclade QC with ARTIC coverage

For a sample with poor Nextclade QC, return to its ARTIC output and inspect:

```text
<sample>.amplicon_depths.tsv
```

Questions to consider:

1. Does the sample contain one or more low-depth amplicons?
2. Do low-depth amplicons correspond to missing regions in the consensus?
3. Does the consensus contain many `N` bases?
4. Is the assigned clade plausible despite incomplete sequence coverage?

This connects **read-level and amplicon-level QC** from `artic-mpxv-nf` with **genome-level QC and lineage assignment** from Nextclade.

## Inspect missing bases in the consensus genomes

Count the number of `N` bases in each consensus genome with:

```bash
awk '
    /^>/ {
        if (name != "") {
            print name, n
        }
        name = substr($0, 2)
        n = 0
        next
    }
    {
        seq = toupper($0)
        n += gsub(/N/, "", seq)
    }
    END {
        if (name != "") {
            print name, n
        }
    }
' "$NEXTCLADE_DIR/yale_testrun1_cladeii.consensus.fasta"
```

A high number of `N` bases indicates unresolved positions in the consensus sequence.

Compare these counts with the `totalMissing` field in the Nextclade results.

---

## Inspect the phylogenetic output

When the dataset contains a reference tree, Nextclade places the query sequences into that phylogenetic context.

The tree output produced by `--output-all` can be used for visualization in tools that support Nextstrain/Auspice JSON.

The phylogenetic placement provides additional context for the clade and lineage assignments.

However, remember that placement depends on the completeness and quality of the consensus sequence. Poor-quality or highly incomplete genomes should be interpreted cautiously.

## Optional: download the dataset before running Nextclade

For the command above, Nextclade automatically downloads the latest compatible dataset into memory.

For a workshop or a reproducible analysis, you may instead download the dataset first:

```bash
nextclade dataset get     --name "nextstrain/mpox/all-clades"     --output-dir "$PROJECT_DIR/0_data/nextclade/mpox_all_clades"
```

Then run:

```bash
nextclade run     --input-dataset "$PROJECT_DIR/0_data/nextclade/mpox_all_clades"     --output-all "$NEXTCLADE_DIR/results"     "$NEXTCLADE_DIR/yale_testrun1_cladeii.consensus.fasta"
```

This has two advantages:

1. the dataset remains available for repeated analyses;
2. the exact dataset files used for the analysis can be retained for reproducibility.

For strict reproducibility, both the **Nextclade software version** and the **dataset version** should be recorded.

Check the software version with:

```bash
nextclade --version
```
